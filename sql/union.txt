## BASIC UNDERSTANDING

UNION:

* Combines result sets
* Removes duplicates

UNION ALL:

* Combines result sets
* Keeps duplicates
* Faster

---

## QUESTION 1: Combine all employees (with duplicates)

Query:
SELECT name FROM employees_current
UNION ALL
SELECT name FROM employees_archive;

Output:
Amit
Neha
Raj
Sneha
Raj
Karan
Meena
Amit

Explanation:

* All rows included
* Duplicate names (Raj, Amit) appear twice

## QUESTION 4: Combine with conditions

## QUESTION 5: Remove duplicates using UNION ALL (advanced)

Query:
SELECT DISTINCT name
FROM (
SELECT name FROM employees_current
UNION ALL
SELECT name FROM employees_archive
) t;

Output:
Amit
Neha
Raj
Sneha
Karan
Meena

Explanation:

* UNION ALL + DISTINCT manually removes duplicates
* Sometimes faster than UNION

## COMMON ERRORS

❌ Different number of columns
❌ Mismatched data types
❌ ORDER BY inside individual queries (wrong placement)

---

## PERFORMANCE INSIGHT (VERY IMPORTANT)

UNION:

* Removes duplicates
* Uses sorting → slower

UNION ALL:

* No duplicate removal
* Faster → preferred in real systems

## BEST PRACTICE (3+ YEARS LEVEL)

* Use UNION ALL by default
* Use UNION only when deduplication required
* Use DISTINCT + UNION ALL for better control
* Always ensure column alignment

---

## FINAL INTERVIEW ANSWER

"UNION removes duplicates and is slower due to sorting, while UNION ALL retains duplicates and is faster. In production systems, UNION ALL is preferred unless deduplication is required."
